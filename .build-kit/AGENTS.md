# Build Kit — Accumulated Learnings

- Routes are auto-discovered by `server.ts` via `glob('dist/src/slices/**/routes{,-*}.js')` — do not manually wire routes into server.ts; the build-state-change/build-state-view skill's "wire up the route" step is a no-op here.
- `src/slices/<context>/` directory names follow the same lowercase-no-spaces convention as the slice folder names already present in each context's `index.json` (e.g. context "Todo List" -> `todolist`).
- Root project (`package.json` at repo root) has its own dependencies separate from `.build-kit/node_modules` — run `npm install` at the repo root, not just inside `.build-kit`, before running `npm run build` / tests.
- When a slice's `specifications[]` is empty and it has no `storylines[]`, do not fabricate business-rule tests — write only a happy-path DeciderSpecification test derived from the command/event fields actually defined in slice.json.
- `HTML_SCREEN` / storyboard nodes on a slice are UI-kit scope, not build-kit scope — the build-* skills only touch `src/slices/**/*.ts` command/event/route code.
- `supabase/migrations/_V0__supabase_stubs.sql` was missing (only `V1__schema.sql.example`, an inactive `.example` file, existed) even though `src/common/testHelpers.ts#runFlywayMigrations` reads it unconditionally — any state-view test errors with ENOENT until this stub exists. Created it with a minimal `CREATE EXTENSION IF NOT EXISTS pgcrypto;` (harmless no-op for schemas that don't need it); extend it only if a future migration needs another Supabase-managed object.
- The build-state-view skill's routes.ts template imports a `readmodel()` helper from `../../../core/readmodel` that does not exist in this project — no such module was ever scaffolded. Query the projection table directly via `getKnexInstance()` from `src/common/db.ts` instead (see `src/slices/todolist/todolists/routes.ts`).
- Running Postgres-container-backed tests (`PostgreSqlContainer`/testcontainers) requires the Docker daemon running, not just the CLI installed — if `docker info` fails with "Could not find a working container runtime strategy" or "context deadline exceeded", run `open -a Docker` and poll `docker info` until it succeeds before retrying the test.
- A slice's `events[]` array can be empty even when the projection must react to an event — check each readmodel's `dependencies[]` for an `INBOUND`/`EVENT` entry instead (title uses spaced form, e.g. "Todo List Defined" for event type `TodoListDefined`).
